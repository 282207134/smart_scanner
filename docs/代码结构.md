# 代码结构与开发入口

## 目录

| 目录 | 职责 |
| --- | --- |
| `lib/backend` | 共用系统摄像头通道、Windows Media Foundation / KMServer、macOS AVFoundation、演示设备和录像 |
| `lib/core` | 协议、文档边界、裁切/展平、自动扫描检测、文件存储、导出及系统 OCR |
| `lib/state` | 连接与拍摄状态、用户设置、页面管理及流程协调 |
| `lib/ui` | 页面和控件，不直接操作设备或实现图像算法 |
| `windows/runner`、`macos/Runner` | 平台原生相机、OCR、权限及窗口接入 |
| `test` | 协议、图像像素、导出、后端、拍摄流程与界面验证 |
| `test/fixtures` | 共享的合成文档样本，不从另一个测试文件导入测试工具 |
| `tool` | 自动检查与实机检查入口 |
| `tool/diagnostics` | 协议、预览帧、OCR、设备与 OpenCV 的排查脚本 |
| `docs` | 原装软件对照、实拍截图和验收记录 |

`build`、`build_temp`、`.dart_tool` 和本机临时截图不纳入版本管理；已有运行包和构建缓存保留在本机。

## 共用拍摄流程

普通文档和书籍都由控制器协调同一流程：检查状态 → 采集并保留原图 → 调用对应图像处理 → 为各页命名并保存 → 更新自动扫描状态 → 恢复拍摄状态。

`ScanFileStore` 管理安全文件名、原图读取和文件路径避重；`DocumentVision` 管理检测和映射；`DocumentExporter` 管理编码和文档输出。书籍使用 `_L`、`_R`，多文档使用 `_01`、`_02`，文件格式和原图保留行为保持一致。

## 检查入口

```text
flutter pub get
./tool/test_windows.ps1
dart run tool/hardware_test.dart
flutter run -d windows --release -t tool/windows_camera_smoke.dart
dart run tool/vision_check.dart <原图路径> <输出目录> [书脊位置]
dart run tool/capture_vision_check.dart
```

实机脚本会使用扫描仪，执行前先关闭扫描客户端及原装软件。`hardware_test.dart` 检查厂商服务；`windows_camera_smoke.dart` 检查系统枚举、不同采集尺寸、缩放后原尺寸照片、旋转、PDF、MP4 和错误恢复，结果在 `build/validation/windows-camera`。它必须通过 Windows runner 运行，检查后重新构建默认入口。离线测试不占用摄像头。`test_windows.ps1` 对每个窗口场景使用独立进程，任一失败立即退出。OpenCV 缓存导出不一致时使用 `refresh_opencv_windows.ps1` 修复，不清空已编译的缓存。

macOS 原生构建和 USB 验收需要 Mac；Windows 检查无法代替它们。
